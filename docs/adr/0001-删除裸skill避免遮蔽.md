# ADR 0001 · 删除旧 trip-planner 裸 skill，避免插件被遮蔽

- 状态：已接受（2026-09-14）
- 影响：维护者本机 skill 环境、插件安装引导

## 背景

本插件的前身是维护者机器上的裸 skill（`~/.agents/skills/trip-planner`，git 克隆）。宿主（ZCode / Claude Code）的技能解析规则是：**裸 skill（`~/.agents/skills/`）优先级高于插件 skill**。两者同名或触发词重叠时，插件 skill 被永久遮蔽——装了插件等于没装。

旧 skill 与本插件触发词高度重叠（都是「做攻略/行程」），并存必然冲突。

## 决策

**蒸馏后删除**。把旧 skill 里经过实战验证、仍有独立价值的三样遗产并入插件主 skill 的 Constraints：

1. 先登录再取数；登录与人机验证交给用户，不代解、不绕过。
2. 每条数据带来源与核实日期；查不到标「待核实」，不许编造。
3. 只读不代操作：不代下单、不代付款。

其余流程（旧版以 Markdown+PDF 交付、携程/飞猪比价为主线）按插件的新主线（特辑风网页 + 两阶段状态机）重写，不做整体继承；PDF 收进可选分支手册（references/pdf.md）。高德网页版路线查询的操作遗产并入 references/amap.md。

删除范围：仅旧 trip-planner 克隆目录。机器上其他第三方 skill（点评、小红书 driver 等）保留不动（插件以链接致谢、不并入）。

## 权衡

- 备选一「改名共存」：治标不治本，触发词仍重叠，遮蔽关系只是换了名字存在；且用户会被两个入口搞糊涂。
- 备选二「裸 skill 优先、插件只做新增」：放弃插件的可安装性与开源分发，与项目目标冲突。
- 代价：依赖旧 PDF 流程的用户需改走插件的 pdf 分支；维护者本机失去旧 skill 的即开即用（由插件接管，体验等价）。

## 后果

- 插件成为唯一入口，无遮蔽问题；触发词唯一。
- 回退方式：旧 skill 是公开 git 克隆，可随时重新 clone 恢复；插件的 amap.md 保留了其路线查询操作的蒸馏版本。
- 维护者记忆指针同步改指本插件仓库。
