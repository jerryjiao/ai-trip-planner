# ADR 0003 · 携程/飞猪以「比价通道」回归，住宿全闭环 + 订房深链

- 状态：已接受（2026-09-14）
- 影响：通道体系（手册十篇）、额度账本、模板住处卡、官网与 README 口径

## 背景

ADR 0001 砍掉了旧版裸 skill 的「携程/飞猪比价为主线」，理由是与新主线（特辑风网页 + 两阶段状态机）冲突，旧流程不做整体继承。此后插件的数据通道只有三平台：小红书（软情报）、大众点评（硬数据）、高德（地图）。

但维护者真实项目的实战验收链路（2026-09 家庭攻略）证明：**住宿是家庭攻略的第一硬需求**——携程承担了住宿选店、档期实读（房价/房型/取消政策）与「带日期店名的订房深链」的实际闭环，家人点深链直达订房页是真实被使用的行为。插件文档与官网停留在「三平台」口径，与实战脱节。

## 决策

携程/飞猪以**「比价通道」**身份回归，职责收窄为口诀第四环「比价定住宿」：

- 携程 = 住宿主查口（选店 / 档期价 / 房型 / 取消政策）+ 订房深链生成。
- 飞猪 = 交叉比价与备用深链，价差如实标注平台。
- 附带职责：门票渠道参考、配图源（收编 photos.md 已有的 Trip.com 提法）。
- 规格照点评通道：先登录再取数（用户完成）、额度账本（每平台详情页 ≤10 次/天）、滑块即停、只读不代订。
- 不做旧版「比价为主线」的全站铺开——它在口诀里是一个环节，不是主线。不配专属脚本（住宿是浏览+实读，点评式浏览器 SOP 已覆盖；脚本等痛点再立）。

## 权衡

- 备选「只做未登录公开页」被否：房型/取消政策/差评原文登录后才全，未登录口径撑不起「真实通道」。
- 备选「官网直接宣传五平台、代码不动」被否：与「如实标注、不冒充」的铁律冲突，属夸大宣传。
- 飞猪深链公式暂不手拼：网页版复制列表页当前 URL（所见即所得），公式待实测收编后补进 hotels.md。

## 后果

- 新增第十篇手册 references/hotels.md；额度账本四行；zine 住处卡「订房直达」按钮组；五平台口径进入官网、README、setup、trip-doctor。
- 与 ADR 0001 的关系：**不恢复旧主线，只收编其实战遗产**——本 ADR 是对 0001 的局部修正，0001 关于交付主线与遮蔽问题的结论不变。
- 回退方式：删 hotels.md、还原模板住处卡与各文档口径即可，无代码耦合（无新脚本、无新依赖）。
