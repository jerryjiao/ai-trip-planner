# ai-trip-planner · 主流程

攻略分两个阶段，**拍板是唯一边界**：

1. **阶段一 · 选方案（发散）**：摸底需求 → 研究先行搜目的地共识 → 每方案一张轻网页（决策级数据）→ 给推荐，等用户拍板。
2. **阶段二 · 细化（收敛）**：版式样板 1 页拍板 → 逐天闭环 → 全站自检 → 部署上线。

顺序口诀：**软情报定玩法 → 硬数据定店 → 比价定住宿 → 地图定事实。**
（软情报=小红书/攻略镜像；硬数据=大众点评；比价=携程/飞猪；地图=高德）

状态持久化在攻略项目目录的 `trip-state.md`（七节形状见文末）。**每个会话从 Step 0 开始**，跨会话靠它续接。

## Step 0 · 会话开局（每次必做）

1. 找攻略项目目录里的 `trip-state.md`：
   - **有** → 读完按状态续接，先向用户复述一句「上次到哪了」，再继续。
   - **无** → 若用户表达的是新攻略需求，走阶段一摸底；若只是问句，先回答再谈开新项目。
2. 环境健康心里有数：工具链/登录态异常会直接卡后续步骤。不确定就跑 `/trip-doctor` 的检查清单（references/setup.md）。
3. 额度账本开张：确认 trip-state.md 里有今日额度记录节（没有就补上，记法见 xiaohongshu.md）。

## 阶段一 · 选方案

### 1. 摸底（需求不全不开工）

一次问清，允许自然对话补齐：**时间**（日期范围/季节）、**人数与构成**（大人/老人/孩子年龄）、**预算档位**、**出行方式**（自驾/公共交通/混合，含活动半径：每天能接受的车程上限）、**偏好**（想干什么/明确不想干什么）。带老人孩子要问红线（如每天在途+游玩总时长上限）。

全部写入 trip-state.md 需求卡。用户说「都行」的地方，按构成给默认假设并写明「假设，可改」。

### 2. 研究先行（搜目的地共识）

每个候选目的地搜一轮「目的地 + 构成关键词」（如带娃/老人/国庆），拿共识口径：适不适合、旺季坑、大体玩法。额度控制在方案期 2-3 次搜索（xiaohongshu.md 的额度政策与间接源降级）。共识写进轻页，注明来源。

### 3. 轻页（每方案一张）

只装**决策级数据**：车程（出发地↔目的地）、住宿可得性（比价通道查档期：有房/紧张/订不到 + 价位档）、吸引点匹配（跟构成对不对路）、门票档位、粗预算。每方案一个 HTML 页（templates/lite 壳），不深调研、不写执行级细节（套餐/时刻表/逐段车程留给阶段二）。

### 4. 推荐与等拍板

给明确推荐（选哪个、为什么、什么情况下选别的），然后**停下等拍板**。用户说「就选X」或 `/trip-go X` 都走阶段门。拍板前不动阶段二。

## 阶段门 · /trip-go

拍板动作三件事：方案状态改「拍板」（其余改「淘汰」，理由留一行）；trip-state.md 阶段推进「细化-样板」；轻页封存（文件保留，状态文件记「已封存」）。整体换方案=回阶段一，已查数据在 trip-state.md 标「可复用」，不重查。

## 阶段二 · 细化

### 5. 版式样板（1 页先拍板）

从 templates/zine 壳起步，做**第一天或 index 页**给用户看风格。用户点头才铺开全站。**永远单版本**：改就是改这份，禁止两套页面并存手工同步。

### 6. 逐天闭环（每天成稿当天核完）

每天的固定顺序：

1. **研究先行**：搜当天主题攻略（动线/时段/避雷/野路子），吸收进当天玩法（额度 2-3 次，紧张时退间接源）
2. **硬数据定店**：点评按品类好评榜选店、进店实读全量（dianping.md 的 SOP 与风控红线）
3. **比价定住宿**：携程选店+档期实读（房价/房型/取消政策），飞猪交叉比价，产出订房深链（hotels.md 的 SOP 与额度红线）
4. **地图定事实**：高德核每段车程（里程/用时/过路费）、坐标、路线图（amap.md）
5. **成稿**：当天页面写完，配图逐张看内容配文（photos.md），文案过 writing.md
6. **未验项清零**：当天所有「待核实」要么核实、要么明示留到行前（记遗留清单）
7. **汇报**：当天查了什么、哪些核实了、剩什么，简短交代

**不带病进下一天**：当天没闭环不开下一天。换整天安排=正常迭代；整体换方案=回阶段一。

### 7. 软情报融入

逐天主体成稿后，把研究期攒下的软情报（贴士/避雷/现场细节）融进对应位置，不单独堆一章。

### 8. 全站自检

- 六视口自适应：1440/1024/820/700/414/360 逐档截图检查（deploy.md 的验收清单）
- 文案复查：writing.md 的 grep 词表全量扫一遍去 AI 味
- 配图复验：新文件名的图逐一再看缩略图（photos.md，批量读图顺序不可靠）
- 锚点跳转、表格横滑、路线图完整性逐页过

### 9. 部署检查点

每轮收尾必须二选一：「**现在部署**」或「**这轮攒着**」，写进 trip-state.md 部署节，不许悬置。部署流程与验收清单见 deploy.md。PDF 导出是可选分支（pdf.md），不做主线维护。

## trip-state.md · 七节形状

```
# trip-state
阶段: 选方案 | 细化-样板 | 细化-dayN | 上线
需求卡: 日期/人数/构成/预算/出行方式与车程半径/偏好（含假设标注）
方案: [{名, 状态: 候选|拍板|淘汰, 理由}]（拍板后轻页标已封存）
逐天进度: {day1: 闭环|进行中|未开始, ...}
额度账本: {小红书搜索: 今日 n/N, 点评进店: 今日 n/N, 携程详情: 今日 n/N, 飞猪详情: 今日 n/N}（跨天滚动，记法见 xiaohongshu.md / hotels.md）
遗留: [待补事项，随项目走]
部署: {上次: 日期与地址, 攒着: [原因]}
```

模板在 `templates/trip-state.template.md`。**它是唯一事实源**：每次状态变化当场写回，不靠会话记忆。

## Constraints（红线，优先级高于任何步骤）

1. **先登录再取数**；登录、扫码、人机验证一律用户本人完成，不代解、不绕过、不重试触发风控。出现滑块/安全限制立即停，交用户处理，恢复后单店慢速。
2. **每条数据带来源与核实日期**；查不到标「待核实」，不许编造。
3. **只读不代操作**：不代下单、不代付款；小红书永久红线只查不发。额度参数是保守经验默认值（非平台规则），可配置。
4. **隐私**：用户攻略产出含真实行程没问题；但本插件仓库、模板、文档、示例零真实行程信息，模板与截图一律虚构占位。
5. **永远单版本**，禁止双轨页面手工同步。
6. 大动作（删文件/覆盖/搬家）前先看 pitfalls.md 的操作纪律。
