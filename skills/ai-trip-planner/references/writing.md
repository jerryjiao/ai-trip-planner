# writing · 成文质量（说人话 + 去 AI 味 + 餐厅梯度 + 汇报节奏）

> 攻略是写给家人看的，不是写给甲方看的。功能性内容（时刻表/价格/导航链接）照实写、不许润色；叙述性内容按本手册把关。

## 说人话原则

一句话检验：**读出来像不像家里人交代事情**。像，就对了；像发布会、像软文、像工作汇报，就重写。

### 黑话翻译表

| 别写 | 写成 |
|---|---|
| 赋能 / 抓手 / 闭环 / 拉通 / 对齐颗粒度 | 直接说那件事（「先买票再进园」不要说「提前锁定入园链路」） |
| 打卡 XX 地标 | 去 XX（要排队就说排队） |
| 绝绝子 / 天花板 / 神仙 | 好吃/好玩，好在哪说一句 |
| 宝子们 / 家人们谁懂啊 | 不用称呼，直接说事 |
| 治愈系 / 松弛感 | 描述具体感受（「下午没安排，累了就在民宿躺着」） |
| 小众秘境 | 人少的地方，少到什么程度给个数 |

### 禁用句式（AI 味重灾区）

- **破折号当连接词**：「……——这是……」整句删掉重写。破折号只允许用在功能性引用（来源标注），不许出现在叙述里。
- **公式体口号句**：「不仅 X，更是 Y」「X 的尽头是 Y」「去 XX，赴一场 Y 之约」「把 Y 交给 X」。全删。
- **总结陈词**：「总之」「综上所述」「值得一提的是」「让我们一起」。
- **排比堆情绪**：三连排比一段只许出现在完全必要的地方（基本没有必要的地方）。

## grep 复查法（文案大改后必跑）

任何一轮大改文案后，全站全文扫一遍禁用词，别靠肉眼：

```bash
grep -rn -e '——' -e '不仅' -e '更是' -e '值得一提' -e '总之' -e '综上' -e '赋能' -e '抓手' \
  -e '绝绝子' -e '天花板' -e '宝子' -e '赴一场' -e '的尽头是' <项目目录>/
```

命中不代表全错（功能性引用允许），逐条判断：叙述里的删，引用里的留。**改完再跑一遍**，防止改 A 带出 B。

## 餐厅梯度规则（每天可直接执行）

1. **数量下限**：每个正餐 1 首选 + 2 备选起步（首选全量实读，备选至少人均/品类/差异化标签/营业时间）。
2. **品类梯度**：备选池按品类广度拉开（正餐/面食/火锅/烧烤/小吃），**锅子类（火锅/砂锅/干锅）全池最多 1-2 席**，不许同品类换名字凑数。
3. **差异化标签**：每家备选一句「跟首选差在哪」（快/近/换口味/老人软食），现场临时换店时能立刻挑。
4. **跨天不重复**：同一家店最多出现一天（明确要二刷的除外，写明二刷理由）。
5. 模板结构见 templates/zine/day.html 的餐厅卡（首选 rlabel / 备选 rlabel alt）。

## 汇报节奏（对用户）

- **逐天慢查，不许急着宣布查完**：每天交代「查了什么、哪些核实了、哪些待核实、下一步」，一块一块说。
- 汇报里数字带来源与日期（「车程 2h20m，高德 9-13 实测」），待核实项明说，不许含糊成「都查好了」。
- 页面正文要求：正文提到餐厅/景点处给**锚点跳转**（`<a href="#lunch">`），每段导航给**高德深链按钮**，实拍图明确「图注写拍到的是什么」。这三样是验收项，写完逐页自检。

## 坑

- 去 AI 味不是删信息：时刻表、价格、套餐内容一字不动，改的只是叙述腔调。
- 引用评价原文允许带原文腔调，但图注/来源标注要写清是平台用户原话。
